# chat-folder joiner

Юзербот на Telethon: вступает по списку ссылок и раскладывает заджойненные чаты по N папкам с заданным количеством чатов в каждой.

## Настройка (общая для обоих способов запуска)

1. `api_id`/`api_hash` — на https://my.telegram.org (App configuration).
2. Скопировать `config.example.json` → `config.json`, заполнить `api_id`, `api_hash`, задать список папок и count на каждую.
3. Скопировать `links.example.txt` → `links.txt` (или свой `.json`, указать `"links_format": "json"` в конфиге — формат: список строк либо список `{"link": "..."}`).

## Способ 1: локально (venv)

```
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

При первом запуске Telethon спросит номер телефона, код из Telegram и (если включена) 2FA-пароль — прямо в терминале. Создастся файл сессии `<session_name>.session` рядом с проектом — при последующих запусках повторного логина не будет.

## Способ 2: Docker

Первый запуск обязательно интерактивный — нужно ввести код из Telegram, стандартный `up -d` для этого не подходит (нет доступа к stdin):

```
docker compose run --rm joiner
```

Логин пройдёт в терминале, `<session_name>.session` сохранится на хосте (весь проект примонтирован как том), контейнер после `--rm` удалится сам, сессия останется.

Дальнейшие запуски (сессия уже есть, ввод не нужен) — в фоне:

```
docker compose up -d
docker compose logs -f
```

`config.json`, `links.txt`/`links.json` и `state.json` читаются/пишутся прямо на хосте (volume `.:/app`) — их можно редактировать без пересборки образа. Пересборка нужна только если поменялся код или `requirements.txt`:

```
docker compose build
```

Остановить фоновый прогон:

```
docker compose down
```

Прогресс в `state.json` сохраняется — повторный `run`/`up` продолжит с того места, где остановились.

## Как это работает

- **Адаптивный троттлинг** (`throttle.py`): темп подстраивается под конкретный аккаунт — ускоряется на успехах, резко тормозит на `FloodWaitError`, уходит в долгий cooldown при частых флудах подряд. Публичные и приватные джойны троттлятся раздельно (разные flood-бакеты у Telegram).
- **Авто-скип** (`joiner.py`): битые/просроченные инвайты, приватные без доступа и т.п. пропускаются мгновенно без штрафа по времени. `FloodWaitError` — не skip, а ретрай той же ссылки после сна. Упор в лимит диалогов аккаунта (`CHANNELS_TOO_MUCH`) или спам-флаг (`PeerFlood`) — полная остановка прогона.
- **Папки собираются по ходу** (`folders.py`), а не в конце: буфер флашится в Telegram каждые `folder_flush_every` успешных джойнов или раз в `folder_flush_interval_sec` секунд.
- **Резюмируемость** (`state.py`): прогресс по каждой ссылке в `state.json`. Прерванный прогон при повторном запуске продолжается с того же места, уже обработанные ссылки не трогаются.
- Ссылки распределяются по папкам **последовательно** по порядку в файле, согласно `count` каждой папки. Ссылки сверх суммарной ёмкости папок помечаются `overflow` и не джойнятся вообще.

## Важно

- Нужен Telegram Premium на аккаунте, если суммарно нужно быть больше чем в 500 чатах, и чтобы влезало по 200 чатов в папку (без Premium лимит папки — 100).
- Стартовые параметры throttle — отправная точка для авто-тюна, а не гарантия безопасности. Если в логе часто мелькает `[cooldown]` — значит аккаунт упирается в потолок, стоит поднять `delay_start`/`delay_min` в конфиге.
- `PEER_FLOOD` в логе — сигнал, что аккаунт словил спам-ограничение. В этом случае стоит сделать паузу на аккаунте (часы, не минуты) перед повторным запуском.
